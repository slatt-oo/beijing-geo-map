# 实现文档：北京地图 Demo（beijing-geo-map）

> 本文回答「做什么、分几步做、每步做到什么程度算完成」。
> 技术细节见 [02-technical-design.md](02-technical-design.md)，数据库设计见 [03-database-design.md](03-database-design.md)。

## 1. 项目目标

用一个可以一键启动的 Demo，完整展示以下四方面能力：

1. **空间数据库设计**：用 PostgreSQL + PostGIS 存储行政区边界和兴趣点（POI），通过空间索引支撑点在面内、范围查询、按距离查询等典型空间查询。
2. **Go 后端**：基于 Gin 提供分层清晰、参数校验严格、可测试的 REST API。
3. **前端地图**：基于 React + MapLibre GL 渲染北京市地图，实现边界交互、POI 聚合、定位、搜索和附近查询。
4. **国内地图的坐标系处理**：数据统一存储为 WGS-84，在前端显示层与高德 GCJ-02 底图对齐。

## 2. 第一版功能范围

| 编号 | 功能 | 用户能做什么 | 体现的技术点 |
|---|---|---|---|
| F1 | 行政区边界 | 看到北京 16 个区的边界；鼠标悬停时高亮并显示区名；点击某个区后地图缩放过去，面板显示面积和各类 POI 数量 | MultiPolygon 存储、几何简化、MapLibre `feature-state` |
| F2 | 我的位置 | 点击「定位」按钮，地图显示自己的位置和精度圈，并提示「你在 XX 区」；浏览器定位失败时，可以在地图上手动点选位置 | `ST_Contains` 点在面内查询、Geolocation API、坐标转换 |
| F3 | POI 标注 | 看到地铁站、高校、景点/博物馆、医院、公园五类 POI；缩小时聚合显示数量；可以按分类开关；点击 POI 查看详情 | bbox 范围查询 + GIST 索引、客户端点聚合 |
| F4 | POI 搜索 | 输入名称模糊搜索，选中结果后地图飞到该点并打开详情 | `pg_trgm` 三元组索引、输入防抖 |
| F5 | 附近查询 | 以「我的位置」或地图上任意一点为中心，查询 N 米内的 POI，地图上画出范围圆，列表按距离排序 | `geography` 精确距离、表达式索引 |

**第一版明确不做**：用户登录与收藏、轨迹记录与回放、热力图和分级着色、MVT 矢量瓦片、线上部署。这些内容见第 6 节「后续阶段」。

## 3. 技术选型一览

| 层 | 选型 | 选择理由 |
|---|---|---|
| 数据库 | PostgreSQL 16 + PostGIS 3.4 | 空间数据的事实标准，空间索引和空间函数最完整 |
| 后端 | Go 1.26 + Gin + pgx v5 + golang-migrate | 性能好，部署是单个二进制；直接用 pgx 手写 SQL，空间查询完全可控 |
| 前端 | React 19 + TypeScript 6 + Vite 8 | 主流组合，类型安全，开发体验好。TypeScript 暂时固定在 6.0，因为 typescript-eslint 8 只支持到 6.0 |
| 地图渲染 | MapLibre GL JS | 开源的 WebGL 地图引擎，支持 GeoJSON 数据源、聚合和 `feature-state` |
| 底图 | 高德公开栅格瓦片 | 无需申请 Key，国内访问快；坐标系为 GCJ-02，需要做纠偏 |
| 前端状态 | TanStack Query + Zustand | 前者管理服务端数据缓存，后者管理地图交互状态 |
| 样式 | Tailwind CSS | 写浮动面板这类 UI 很快 |
| 运行 | Docker Compose | `docker compose up` 一键启动全部服务 |
| CI | GitHub Actions | 每次推送自动运行测试和构建 |

## 4. 数据来源

| 数据 | 来源 | 坐标系 | 规模 | 许可 |
|---|---|---|---|---|
| 行政区边界 | 阿里云 DataV.GeoAtlas，`110000_full.json` | GCJ-02 | 16 个区，约 100 KB | 来自高德开放数据，仅用于非商业 Demo |
| POI | OpenStreetMap，经 Overpass API 导出快照 | WGS-84 | 约 4000 余条 | ODbL，界面和 README 中需要署名 |
| 底图 | 高德公开瓦片地址 | GCJ-02 | — | 非官方开放接口，仅用于非商业 Demo |

POI 规模的依据是 2026-10 通过 Overpass 统计的各分类数量：景点/博物馆 1704 个、公园 1374 个、医院 453 个、高校 185 个，地铁站数百个（换乘站在 OSM 中可能有多条记录，导入时会去重）。

**两份数据快照都会提交到仓库**（`data/raw/`），所以构建和启动都不依赖外网。实测 Overpass 接口不稳定：没有 User-Agent 的请求会被拒绝（406），频繁请求会被限流或超时（429、504）。因此拉取脚本 `scripts/fetch_osm_pois.sh` 必须带 User-Agent 并支持重试，并且只在需要更新快照时手动运行。

## 5. 阶段计划

每个阶段结束时项目都处于可运行状态，并作为独立的提交推送到 GitHub。

### 阶段 0：仓库、文档与骨架

- **任务**
  - 初始化仓库，编写本文档、技术方案和数据库设计（已完成）。
  - 搭建后端 Go 模块骨架，提供 `/api/v1/health` 接口。
  - 搭建前端 Vite 骨架。
  - 编写 `docker-compose.yml`（`db`、`backend`、`frontend`）、`Makefile` 和 `.env.example`。
  - 配置 GitHub Actions 的三个任务，并让它们在空骨架上跑通。
- **验收标准**
  - `docker compose up --build` 启动成功，`curl localhost:8080/api/v1/health` 返回数据库连接正常。
  - CI 全部通过。

### 阶段 1：数据层

- **任务**
  - 编写迁移 `000001`（扩展和表结构）与 `000002`（分类种子数据）。
  - 实现 `internal/geo` 坐标转换，并建立前后端共享的测试样例 `testdata/coord_cases.json`。
  - 编写 OSM 拉取脚本，把两份数据快照提交进仓库。
  - 实现导入器 `cmd/importer`，在 `docker-compose.yml` 中加入一次性的 `seed` 服务。
  - 编写 repository 层的集成测试。
- **验收标准**
  - `docker compose up db seed` 执行后，`district` 表有 16 行，`poi` 表约 4000 行，`district_id` 的填充率超过 95%。
  - 重复执行导入，各表行数不变。
  - 集成测试全部通过。

### 阶段 2：后端 API

- **任务**
  - 实现 9 个接口，包括参数校验、统一错误格式和中间件（日志、panic 恢复、超时、gzip）。
  - 编写 handler 层单元测试。
- **验收标准**
  - 用 curl 调通全部接口，返回内容与技术方案中的接口示例一致。
  - 单元测试和集成测试全部通过。
  - 在文档中记录各接口在本地的实测耗时。

### 阶段 3：前端地图

- **任务**
  - 接入底图，实现坐标转换模块 `coord.ts`。
  - 实现行政区图层的悬停高亮、点击缩放和区详情面板。
  - 实现 POI 图层：按视野加载、聚合、分类筛选和详情弹窗。
- **验收标准**
  - 在浏览器中，区边界和 POI 与底图上的道路、建筑对齐，没有明显偏移。抽查点为天安门、鸟巢、北京大学。
  - 悬停、点击、聚合、筛选全部可用，截图存档。

### 阶段 4：定位与查询

- **任务**
  - 实现定位按钮，以及定位失败时在地图上点选的兜底模式。
  - 实现搜索框。
  - 实现附近查询：半径切换、范围圆、结果列表、右键设置查询中心。
- **验收标准**
  - 技术方案第 10 节的手工验证清单全部通过。

### 阶段 5：打磨与交付

- **任务**
  - 完善加载中、空结果和出错时的界面提示。
  - 完善 README：截图、一键启动说明、架构图、数据署名、CI 徽章。
  - 清理代码和配置。
- **验收标准**
  - 在一台只装了 Docker 的机器上，clone 仓库后执行 `docker compose up --build` 就能完整使用。
  - CI 全部通过。

## 6. 后续阶段（第一版不做）

数据库设计中已经为这些扩展留好了位置，具体表结构草案见数据库设计文档第 9 节。

| 方向 | 内容 |
|---|---|
| 用户与收藏 | 新增 `app_user`、`user_favorite` 表，使用 JWT 登录，用户可以收藏 POI、添加自定义标注点 |
| 轨迹 | 新增 `track`、`track_point` 表，用 `ST_MakeLine` 生成路线，前端动画回放 |
| 统计可视化 | 按各区 POI 密度分级着色，增加热力图图层 |
| 性能 | 用 `ST_AsMVT` 输出矢量瓦片。由于底图是 GCJ-02，需要在服务端完成坐标偏移 |
| 中文搜索 | 引入 `pg_bigm`（二元组）或 `zhparser`（中文分词） |
| 部署 | 部署到线上环境，提供可公开访问的地址 |

## 7. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 桌面版 Chrome 依赖 Google 定位服务，在国内经常定位失败 | F2 不可用 | 提供在地图上点选位置的兜底模式；Safari 使用苹果定位服务，可以正常定位 |
| 高德公开瓦片地址不可用或被限制 | 底图无法显示 | 底图地址可以配置，切换到 OSM 等 WGS-84 底图时，一个开关即可关闭坐标转换 |
| Overpass 接口不稳定 | 无法更新 POI 快照 | 快照提交在仓库中；拉取脚本带 User-Agent 和重试 |
| GCJ-02 转 WGS-84 没有解析解 | 导入的边界存在微小误差 | 使用迭代法反算，收敛阈值约 1 厘米，对 Demo 来说可以忽略 |
| `pg_trgm` 对两个字的查询无法使用索引 | 「北大」这类查询会全表扫描 | 4000 条数据下全表扫描也是毫秒级；后续可以引入 `pg_bigm` |
| DataV 边界和 OSM 数据的边界不完全一致 | 边界附近少量 POI 匹配不到所在区 | `district_id` 允许为空，接口和界面都能正确处理 |
